This page gets you from nothing to a working setup: a project, an agent Overmind understands, production data flowing in, and your first dataset scored. Each step links to the page that covers it in depth.

<Steps>
  <Step title="Create your account and project">
    Sign up at [console.overmindlab.ai](https://console.overmindlab.ai). Everything in Overmind lives inside a **project**: agents, traces, datasets, runs, models, keys. Create one per product or use case; you can add more later and switch from the project menu. See [Projects & Administration](/platform/administration).
  </Step>
  <Step title="Scan your repository">
    Connect GitHub (or paste a public repo URL) and let Overmind scan the branch your agent lives on. The scan discovers your agents and maps their prompts, tools, and control flow. Check the flow graph against reality before moving on. See [Agents](/core/agents).
  </Step>
  <Step title="Get traces flowing">
    Create an API key under **Settings → API keys**, then get traces flowing whichever way suits your codebase. Add the tracing SDK to your app, or let Overmind add observability at the repo level, where it writes the missing tracing code and opens a PR against your branch. If you already collect traces in another tool (Langfuse, LangSmith, and others), connect it and import what you have. Set the agent identity in the SDK so traces land on the right agent. See [Observability](/core/observability).

    ```python
    from overmind import init

    init(
        agent_name="Support Triage",
        service_name="my-service",
        environment="production",
    )
    ```
  </Step>
  <Step title="Build your first dataset">
    Once traces are arriving, select a representative batch in Observability and create a dataset from them, or drag a CSV/JSONL file you already have onto the Datasets page. Open the dataset and run the analysis to get a score and readiness verdict. See [Datasets](/core/datasets).
  </Step>
  <Step title="Measure something">
    Review the evaluators Overmind proposes for your agent, accept the few that match what you care about, and put them in an eval set. Evaluators marked for trace scoring start scoring incoming traffic; run the set against your dataset and you have a baseline. See [Eval](/agent-testing/eval).
  </Step>
</Steps>

The console's **Get started** page tracks these same steps as a checklist, so you always know what's next.

## Where to go from the baseline

The first five steps put you in a position most teams never reach with in-house tooling: real data, curated examples, and a trusted score. What comes next depends on what the score tells you.

<CardGroup cols={2}>
  <Card title="The score should be higher" icon="arrow-trend-up" href="/agent-testing/optimizers">
    Run the Optimizer. It proposes code changes, tests each against your dataset and metrics, and opens the winner as a PR.
  </Card>
  <Card title="Cost or latency is the problem" icon="gauge-high" href="/models/training">
    Fine-tune a smaller model on your own data and benchmark it against the model you run today.
  </Card>
  <Card title="You're not sure what's failing" icon="magnifying-glass" href="/core/observability">
    Filter to low-scoring traces and read them. The trace timeline and transcripts turn vague quality complaints into specific defects.
  </Card>
  <Card title="The data needs work first" icon="database" href="/core/datasets">
    Open the dataset and follow its insights: fix the hard gates, then the high-severity findings, and keep the commit history honest.
  </Card>
</CardGroup>
