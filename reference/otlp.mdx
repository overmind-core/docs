| Field | Contract |
| --- | --- |
| Endpoint | `POST /api/v1/traces` |
| Transport | OTLP/HTTP protobuf or JSON |
| Content type | `application/x-protobuf` or `application/json` |
| Compression | Gzip supported |
| Authentication | Project/account API key in a supported header |
| Root | Span with no parent; spans sharing a `trace_id` form a trace |

There is no JavaScript tracing SDK in the current platform. Use an OpenTelemetry exporter in JavaScript/TypeScript or any other supported language.

An explicit `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` includes the complete path. A generic exporter base endpoint may append its own `/v1/traces`; verify the actual request path instead of appending twice.

## Identity and evidence

| Attribute | Purpose |
| --- | --- |
| `overmind.capability.id` | The capability binding: known UUID or slug |
| `overmind.capability.name` | Display label; does not bind |
| `overmind.project.id` | Project attribution when required by the credential |
| `overmind.span.type` | `entry_point`, `workflow`, `tool_call`, `function`, `llm_call`, `retrieval` |
| `conversation.id` | Group related traces into a session |
| `service.name` | Emitting service |
| `code.namespace`, `code.function.name` | Source function identity |
| `vcs.ref.head.revision` | Emitting revision |
| `inputs`, `outputs` | Captured operation evidence where supplied by the SDK |
| `overmind.unit_kind` | Run/turn metadata |
| `overmind.delivery` | Delivered-result metadata |

The ingest path also normalizes supported GenAI, OpenLLMetry and OpenInference attributes for messages, model identity, tools and usage, including Claude API, Claude Code and OpenRouter spans. Evidence that was not emitted remains unavailable.

For Claude API traces, add a Custom destination in the Claude Console with the API base URL plus `/api` as the OTLP endpoint URL and an `X-Api-Key` request header. Claude Code exports prompts and tool details with its `OTEL_LOG_*` settings; model responses require its detailed tracing.

For OpenRouter Broadcast, add an OpenTelemetry Collector destination with the API base URL plus `/api/v1/traces` as the endpoint and `{"X-Api-Key": "<key>"}` as the headers.

Span identity can override resource identity for applications serving multiple capabilities. Unknown capabilities are stored as unbound; ingestion does not create a capability.

Trace ingest and stored-evidence reads do not require remaining model credits. Model-backed scoring is a separate operation.
