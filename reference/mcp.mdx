The Streamable HTTP endpoint is `/api/mcp/` on the selected deployment. MCP shares domain services with REST and the Console. It is not a generic HTTP proxy.

Use this after [connecting Overmind](/how-to/connect). Supply or select the named resource in your conversation; the agent reads the contract rather than guessing IDs.

## Discovery and scope

| Surface | Contract |
| --- | --- |
| `list_projects` | Authorized active projects, pagination and `connection.mcp_url` |
| `overmind://interface/current` | Connected contract version, permission-scoped catalogue fingerprint and interface metadata |
| Project tools | Account connections pass `project_id` explicitly |
| Project resources | Add `?project_id=PROJECT_ID` or follow the returned scoped link |
| Project API key | Restricted to its bound project |
| `get_credit_balance` | The connection owner's account balance and usage by service; see [credit reporting](/reference/mcp#credit-reporting-and-task-budgets) |

Use the connected `tools/list`, `prompts/list` and resources for complete argument schemas. Tool availability depends on permissions and the deployed version; a static tool count is not a capability guarantee.

## Authentication

Account connections sign in with OAuth through the deployment's login and consent flow; `overmind init` configures this. API-key connections use `X-Api-Key` or a supported bearer header. Account keys reach authorized projects; project keys retain narrower scope. MCP OAuth tokens do not authenticate ordinary CLI file transfers.

Read permission exposes inspection operations; writes require the operation's permission scope. Expiry, account state and membership continue to apply.

## Credit reporting and task budgets

Use `get_credit_balance` to read the connection owner's account balance, lifetime grants and spending, and usage by service. Account and project keys return account-wide figures; no `project_id` is required. Amounts are exact decimal strings in credits: 100 credits = 1 USD.

<AgentPrompt text="Check my Overmind credit balance. You have a budget of 500 credits for this task. Check estimated costs before launching paid work, monitor recorded spending, and stop before starting more work that would exceed the budget." />

Save the initial report's `observed_at` and pass it as `since` on subsequent calls. `usage.spent_credits` reports account charges recorded since that timestamp, including charges without a project assignment. `usage.by_service` breaks down that spending. Balance, grants and lifetime spending stay account-wide lifetime totals. Top-ups do not reduce usage. Omit `since` for lifetime usage.

Reporting does not reserve credits or enforce a hard task cap. Concurrent spending within the reported scope is included; unposted charges and external coding-agent costs are excluded. Recorded usage can lag work already in progress. A zero recorded total does not establish that pending work is free. When `billing_enabled` is false, the deployment meters usage without enforcing a credit balance.

## Resources

| URI | Content |
| --- | --- |
| `overmind://project/current` | Project identity, scan provenance and Console URL |
| `overmind://activity` | Project activity with task and asset references, and onboarding milestones (`path=agent` or `path=data`) |
| `overmind://dataset-upload` | CLI handoff, format limits, package manifest and runtime requirements |
| `overmind://dataset-export` | Version export guidance |
| `overmind://checkpoint-download` | Checkpoint download guidance |
| `overmind://connector-setup` | Provider-credential CLI handoff |
| `overmind://capabilities/{capability}` | Saved capability map and related state |
| `overmind://traces/{trace_id}` | Recorded span evidence |
| `overmind://datasets/{dataset}` | Cells, source facts and dataset state |
| `overmind://eval-runs/{eval_run}` | Frozen run state and result evidence |
| `overmind://finetunes/{job_id}` | Training state, pinned inputs and monitoring |
| `overmind://deployments/{deployment}` | Serving identity, readiness and metrics |
| `overmind://operations/{id}` | Recorded events and separate progress clocks |
| `overmind://jobs/{kind}/{id}` | Workflow-specific job state |

Follow returned resource links for packages, revisions, bindings and data-first workflows. Their identifiers and pagination belong to the connected contract.

## Jobs, pagination and retries

Background operations return durable identities. `get_job(kind=..., id=...)` reads the receipt; `inspect_operation` pages stored events without waking a worker. Use returned polling guidance while active and next actions after completion.

Requests that accept a stable key recover the same work when the key and payload match. Changed payloads conflict. Do not assume every mutation is idempotent: `run_evaluation`, for example, creates new runs.

Pagination can be limited by both item count and response bytes. Follow returned cursors, offsets, `collections` descriptors and `evidence_resource` links for complete retained evidence.

Tool errors include a structured code, message, retryability and field details where applicable. Authentication and authorization failures remain distinct from workflow failures.

## Prompts and local handoffs

Prompts include `author-dataset-transformation`, `develop-model-from-data`, `investigate-capability`, `instrument-repository`, `prepare-evaluation`, `evaluate-change`, `finetune-capability`, `optimize-capability`, `compare-models`, `ship-model`, `upload-dataset-file`, `export-dataset`, `connect-traces` and `download-checkpoint`.

The CLI transfers bytes and runs local repository work. Provider secrets enter protected local configuration or the appropriate Console flow, not MCP tool arguments. See [Connect your coding agent](/how-to/connect).
