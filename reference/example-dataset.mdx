## Source facts

The source is a CSV of synthetic ecommerce transactions. Its target is `is_fraud`. The [dataset card](https://huggingface.co/datasets/apex0data/ecommerce-fraud-detection-synthetic-10k-sampl/blob/main/README.md) describes the source and lists an MIT license.

The available fields are `transaction_id`, `timestamp`, `user_id`, `transaction_amount`, `merchant_category`, `device_fingerprint`, `ip_address` and `is_fraud`.

## What preparation should establish

The coding agent inspects which transaction fields are available at prediction time and how related observations should be grouped. It keeps the target out of model input and retains the original source, preparation and exact versions used by consumers.

For a binary decision, the supplied hard label can become a reference over non-fraud and fraud options in an explicit order. This does not imply that the source contains calibrated probabilities.

Class imbalance matters: predicting non-fraud for every row gives 95.8% accuracy on the full source. Inspect fraud precision, recall and coverage alongside aggregate accuracy. Repeated users, devices or IPs need examination before choosing a split; the agent should explain its choice.
