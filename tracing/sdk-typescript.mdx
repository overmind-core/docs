---
title: TypeScript SDK
description: There is no TypeScript tracing SDK; instrument Node.js with OpenTelemetry against the OTLP endpoint.
---

<Warning>
No TypeScript SDK ships with the current platform. The `@overmind-lab/trace-sdk` package on npm predates the current ingest contract — it does not stamp the attributes below. Do not install it.
</Warning>

Node.js services trace like any other OpenTelemetry client:

- Export OTLP/HTTP protobuf to the [OTLP endpoint](/core/observability#the-otlp-endpoint) with `x-api-key` in the exporter headers.
- Stamp `overmind.capability.id` as a resource attribute — the capability's UUID or its slug from `overmind.toml` — so spans bind to the capability. `overmind.capability.name` is an optional display label and never binds.
- Mark the run boundary with `overmind.span.type = "entry_point"` on the root span and put the run's input and output on it as `inputs` / `outputs`, so [trace scoring](/agent-testing/trace-scoring) has an answer to judge and a root for the trajectory.
- Put `conversation.id` on every span of a multi-turn exchange to group them into a session.
- Optionally set `overmind.intent`, `overmind.expectations` and, on the root, `overmind.reference_trajectory`.

The [attribute table](/core/observability#the-attributes-overmind-reads) lists every key the pipeline reads, including the OTel GenAI and OpenLLMetry conventions that the OpenAI and Anthropic instrumentations for Node already emit.
