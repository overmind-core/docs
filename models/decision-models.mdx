A decision model reads a **state** — a ticket, a document, a conversation — and answers **questions** about it with a probability for every option. It does not write text. Use it where your agent classifies, routes, approves or rates: it is faster and cheaper than a chat model, and its probabilities tell you how sure it is.

You train one the way you train a chat model: shape a dataset in the [Data Workshop](/core/datasets), start a job, and compare the trained model with its base on held-out data.

## Decision rows

A decision row puts the request in `input` and the answers in `expected_output`:

```json
{"input": {
   "state": "Ticket: I was charged twice for order 1002. Fix it now!",
   "questions": {
     "route":  {"type": "choice", "instructions": "Which team handles this ticket?",
                "criteria": {"billing": "Billing and payments", "shipping": "Delivery"}},
     "urgent": {"type": "noul",   "instructions": "Is the customer asking for urgent help?"},
     "mood":   {"type": "score",  "instructions": "How upset is the customer?",
                "criteria": ["calm", "annoyed", "angry"]}}},
 "expected_output": {"route": "billing", "urgent": "true", "mood": 2}}
```

| Question | Criteria | Answer |
| --- | --- | --- |
| `choice` | An object of option keys and their descriptions (2–255) | An option key |
| `noul` | Optional descriptions of `true` and `false` | `true` or `false` |
| `score` | A list of levels, lowest first (2–255) | The level's index: `0`, `1`, … |

An answer can also be a spread of weights, such as `{"billing": 3, "shipping": 1}`; Overmind normalises it. Every question needs an answer. A row accepts up to 255 options or levels and 100 questions; each model has narrower limits, listed in [Models](#models). A job is refused when a row of its training or evaluation version exceeds the chosen model's limits, and such a request returns 400.

The dataset page shows **Ready for decision training** (or **evaluation**) when every row is valid, and otherwise names the first row that is not and why. It also warns, without blocking use, when an option is the answer in fewer than 5 rows, or when one answer covers 90% or more of 10 or more rows. Decision rows are only for decision models: chat training, eval runs and the optimiser refuse them. A coding agent connected over [MCP](/platform/mcp) reads the format from `overmind://decision-models`.

## Train

<Steps>
  <Step title="Shape the data">
    A **training** dataset of decision rows, and optionally an **evaluation** dataset of decision rows with different examples.
  </Step>
  <Step title="Start a job">
    On the dataset page, select **Train a decision model**, or open **Training → Decision models → New decision job**. Choose the training data, the evaluation data and a base model. The dialog offers up to three unranked picks among the models that fit: **Strongest score** (highest Decision Index), **Smaller** (highest index at most half the strongest's size) and **Smallest that fits**. A model that does not fit is unavailable, with the reason. Nothing is preselected. Over MCP, `check_decision_readiness` returns the same picks and `start_decision_job` starts the job; over REST, `POST /api/decision-jobs/recommend/` and `POST /api/decision-jobs/`.
  </Step>
  <Step title="Follow it">
    The job runs **Queued → Running → Succeeded**, through **Evaluating** when it has evaluation data, or ends **Failed** or **Cancelled**. Its versions are frozen when it starts, so later versions do not change it. Cancel stops it while it is queued, running or evaluating.
  </Step>
</Steps>


## Evaluation

With evaluation data, the job scores the base model and the trained model on every row once training ends:

| Metric | Meaning |
| --- | --- |
| **Accuracy** | How often the most likely option is the right one, over answers with one right option, shown beside the majority baseline |
| **Log loss** | How much probability the model gave the right answer; lower is better |
| **Brier** | How far the probabilities are from the answers; lower is better |

An answer given as weights has no single right option and counts only in log loss and Brier. The job's `evaluation` also carries, per question, accuracy, the majority baseline, macro F1, and per-option precision, recall, F1 and a confusion matrix; the Console shows per-question accuracy. Rows a model could not answer are counted under `unanswered` by reason and mark the evaluation **partial**; with no answered rows it is **failed**. A warning counts training rows that overlap the evaluation version.

## Use the model

A succeeded job answers System One requests:

```bash
curl https://api.overmindlab.ai/api/decision-jobs/$JOB_ID/systemone/ \
  -H "Authorization: Bearer $OVERMIND_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"state": "Ticket: where is my parcel?",
       "questions": {"route": {"type": "choice", "instructions": "Which team handles this?",
                               "criteria": {"billing": "Billing", "shipping": "Shipping"}}}}'
```

```json
{"model": "OvermindLab/qwen-3.5-0.8B-decision",
 "answers": {"route": {"type": "choice", "choice": "shipping", "confidence": 0.94,
                       "probabilities": {"billing": 0.06, "shipping": 0.94}}},
 "usage": {"input_tokens": 61, "output_tokens": 0}}
```

`POST /api/decision-models/{model}/systemone` (with `project` in the body) answers with a catalog model as published, without training. A `noul` answer is `{"noul": p}`, the probability of `true`; a `score` answer carries `score` (the expected level), `confidence` and `probabilities` by level index.

A model that has been idle starts again on its first request: the request returns **503** `warming` with `Retry-After`, and the retry is answered. A model that cannot answer returns **503** `unavailable` with a `reason`: `boot_failed`, `adapter_missing` or `runtime_error`.
