## Core

| Term | Meaning |
| --- | --- |
| **Agent** | Overmind's model of an agent that lives in your repository and serves real traffic, discovered by repo scan or created from telemetry, never built in the console. See [Agents](/core/agents). |
| **Flow graph** | The interactive map of an agent's control flow produced by a repo scan. |
| **System prompt** | The prompt the agent runs with, lifted from the code and shown on the agent's Overview tab. |
| **Optimisable / fixed elements** | The parts of an agent the Optimiser may change versus the parts it must not, declared in the agent's evaluation spec. |
| **Trace** | The full record of one end-to-end operation: a tree of spans under one root. |
| **Span** | One unit of work inside a trace: a model call, tool invocation, or function. |
| **Session** | A group of traces forming one multi-turn conversation. |
| **Trace scoring** | Automatic evaluation of traces as they arrive, by the owning agent's evaluators marked for trace scoring. |
| **Connector** | A read-only connection to an external observability tool (Langfuse, LangSmith, Braintrust, Opik, Helicone, Arize Phoenix) that imports its traces. |
| **Observability PR** | A pull request Overmind opens against your repository to add the missing tracing code. |
| **Datapoint** | One example in a dataset: input, optional expected output, optional extras, and, when built from a trace, a link to its source trace. |
| **Intent** | What a dataset is for, fixed at ingestion: **eval**, **fine-tuning**, or **unstructured**. Changing intent means re-ingesting into a new dataset. |
| **Surface** | For trace-built datasets: the **agent** surface (agent input to delivered answer) or the **model** surface (the raw LLM call inside). |
| **Data Workshop** | The dataset working surface: analysis, score, verdict, insights, fixes, and version history. See [Datasets](/core/datasets). |
| **Verdict** | The Workshop's readiness call on a dataset: Ready, Ready with warnings, or Not ready. |
| **Pillar** | A weighted area of dataset health (coverage, uniqueness, safety, agent fit, and so on) that checks roll up into. |
| **Insight** | One finding in a dataset, with severity, evidence, and a proposed fix, from either the deterministic pass or the analyst pass. |
| **Dataset commit** | One entry in a dataset's version history (seed, fix, edit, or restore), recording the row diff and the score at that point. |

## Agent Testing

| Term | Meaning |
| --- | --- |
| **Evaluator** | A versioned, reusable scorer: one question asked of a response. Kinds: LLM judge, deterministic, trajectory, agentic, statistical, decision graph. See [Eval](/agent-testing/eval). |
| **Rubric / checklist** | The plain-language grading criteria of an LLM judge, compiled into weighted atomic questions; items can be gates that force a fail. |
| **Pass threshold** | The score at or above which an evaluator counts a result as passing. |
| **Eval set** | A named group of an agent's evaluators; members serve a **generative** role (score run outputs) or a **trace-scoring** role (score live traffic). |
| **Eval run** | One experiment: a data source × model variants × evaluators, with results compared against a baseline variant. |
| **Variant** | One column of an eval run: a pinned model (and optionally prompt version) that either grades existing traces or generates fresh outputs. |
| **Baseline** | The variant (or score) everything else is measured against. In eval runs, the reference column; in optimisation, iteration zero; in training, the agent's current production model that a fine-tune is benchmarked against. |
| **Sample** | One normalised trace under evaluation for one variant; samples that can't be faithfully reconstructed are marked **degraded** and excluded from aggregates. |
| **Score outcome** | The type of a scoring result: Scored, Abstained, Not applicable, Skipped, or Error. Only Scored results feed averages and pass rates. |
| **Annotation** | A human label on a sample, used to calibrate judges. |
| **Candidate** | One proposed code change in an optimisation run: a real git diff, replayed over the dataset and scored. |
| **Iteration** | One round of an optimisation run: generate candidates, validate, replay, score, accept or discard. |
| **Smoke test** | The pre-flight check that an optimisation run can actually invoke the agent's entrypoint. |
| **Executioner** | The local process started by the `overmind` CLI that applies candidate diffs and runs your agent in your environment. |
| **Plateau** | Consecutive iterations without improvement. The signal to stop optimising and consider training. |

## Models

| Term | Meaning |
| --- | --- |
| **Experiment (training)** | One model + settings combination within a training run; up to four run in parallel. See [Training](/models/training). |
| **Tier** | A size class in the model catalogue, compact through large. |
| **LoRA / adapter training** | Fine-tuning that trains small adapter matrices instead of all weights. Cheaper, and on small datasets usually a match for full fine-tuning. |
| **Validation split** | The slice of training data held back to measure learning; trace-safe grouping keeps related rows on one side. |
| **Contamination guard** | The rule that excludes any training row whose source trace also appears in the eval dataset. |
| **Checkpoint** | A model state saved as training progresses; the final weights are what a run exports. |
| **Baseline delta** | Fine-tune score minus baseline score, per metric. The headline result of a training benchmark. |
| **Model reference** | A deployed model's callable ID, shaped `ft-<hash>-<base>`, used as the `model` field in the inference API. |
| **Deployed model** | A fine-tune served on Overmind: Queued → Quantizing → Deploying → Warming → Ready. Deleting is irreversible and removes the weights. See [Inference](/models/inference). |
| **Model PR** | The pull request that switches your agent to a fine-tuned model in your repository. |

## Platform

| Term | Meaning |
| --- | --- |
| **Project** | The scoping unit for everything: agents, data, runs, models, keys, members. See [Projects & Administration](/platform/administration). |
| **Job** | Any tracked background task (fine-tuning, dataset analysis, eval, model PR) listed in the Jobs view. |
| **API key** | The `ovr_`-prefixed credential for tracing, OTLP ingest, the CLI, and the inference API; pinned to one project. |
| **Credits** | The balance that compute-consuming work draws on; managed under Settings alongside the usage history. |
