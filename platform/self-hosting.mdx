The platform is one repository, [overmind-core/overmind](https://github.com/overmind-core/overmind): the Django API (`overbae/`), the React Console (`frontend/`), the Python SDK and CLI (`overmind/`), and the Modal workers for training and serving (`overbae/modal/`). The hosted product at overmindlab.ai runs this same code.

## Requirements

Docker with Compose, [uv](https://docs.astral.sh/uv/) for anything Python outside the containers, and [Bun](https://bun.sh/) for the Console. The API refuses to start without Modal credentials, the S3 checkpoint archive keys, `HF_TOKEN`, and `INFERENCE_API_URL` / `INFERENCE_API_KEY` — see [Training and serving](#training-and-serving).

## Start the stack

```bash
git clone https://github.com/overmind-core/overmind.git
cd overmind
cp .env.example .env
docker compose up -d
cd frontend && bun install && bun run dev
```

Compose starts Postgres, Redis, and the API. Fill the required keys in `.env` before `docker compose up`. The API is `http://localhost:8000`. The Console is `http://localhost:5173`.

Leave `CLERK_API_SECRET_KEY` blank in `.env`. Set `VITE_SELF_HOSTED=true` and leave `VITE_CLERK_PUBLISHABLE_KEY` blank in `frontend/.env.development.local` (see `frontend/.env.example`). The first visit creates the operator account; later visits sign the same email back in. Project invites still create a pending row when Clerk is off — the invitee signs in with that email; no invitation email is sent.

To use Clerk, put the publishable key in `frontend/.env.development.local` as `VITE_CLERK_PUBLISHABLE_KEY`, omit `VITE_SELF_HOSTED` (or set it false), and put the secret in `.env` as `CLERK_API_SECRET_KEY`. `CLERK_AUTHORIZED_PARTIES` defaults to `http://localhost:5173`. With Clerk blank, the API still accepts project API keys and guest sessions.

`DJANGO_ADMIN_PATH` sets the Django admin path (default `admin`). Then create a project and follow the [Quickstart](/quickstart) with `overmind init --env local`.

For a demo workspace:

```bash
docker compose exec api python manage.py seed_demo
```

## Environment reference

`.env.example` is the operator contract. Every variable is read by `docker-compose.yml` or `overbae/settings.py`.

### Core

| Variable | Purpose |
| --- | --- |
| `DJANGO_SECRET_KEY` | Django's signing key; the default is an insecure development value |
| `DJANGO_DEBUG` | `True` or `False` (settings default `False`). Off, Postgres connects with `sslmode=require` |
| `DJANGO_ALLOWED_HOSTS` | Comma-separated hostnames the API answers for |
| `DJANGO_CORS_ALLOWED_ORIGINS` | Comma-separated Console origins; ignored while `DJANGO_DEBUG=True` (all origins allowed) |
| `FIELD_ENCRYPTION_KEY` | Fernet key for stored connector credentials. Unset, one is derived from `DJANGO_SECRET_KEY`; the API prints a warning at startup when `DJANGO_DEBUG=False` |
| `FRONTEND_URL` | Where the Console lives (default `http://localhost:5173`), for links in prompts and emails |
| `TRACE_SETTLE_SECONDS` | How long a trace with no root span stays `live` before it reads `interrupted` (default `600`) |
| `OPENROUTER_API_KEY` | Routed model calls: judges, eval-run generation, the optimiser's scoring, frontier inference |

Postgres and Redis use the Compose services. Override `POSTGRES_*`, `CELERY_BROKER_URL`, `CELERY_RESULT_BACKEND`, and `CACHE_URL` to point elsewhere.

The API needs at least one of `CURSOR_API_KEY`, `OPENROUTER_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, or `GEMINI_API_KEY`. Without `CURSOR_API_KEY`, `OPENROUTER_API_KEY` is required.

### The Data Workshop agent

The dataset agent runs on the first key it finds, in this order: `CURSOR_API_KEY`, `OPENROUTER_API_KEY`, then `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, or `GEMINI_API_KEY`. Both engines take the same tools and emit the same events. With none set the workshop page opens and the agent reports that it is not configured. `OPENAI_API_KEY` also serves embeddings (`text-embedding-3-small`) for the `embedding_cosine` statistical evaluator.

### Training and serving

Startup requires `FINETUNING_BACKEND=modal` (the settings default), Modal tokens, the S3 checkpoint archive, `HF_TOKEN`, `INFERENCE_API_URL`, and `INFERENCE_API_KEY`.

| Variable | Purpose |
| --- | --- |
| `FINETUNING_BACKEND` | Must be `modal` at startup |
| `MODAL_TOKEN_ID`, `MODAL_TOKEN_SECRET`, `MODAL_ENVIRONMENT` | Modal training and serving workers, deployed with `modal deploy` of `overbae/modal/modal_vllm_worker.py`, `register_model.py`, and `modal_sft_worker.py`. `MODAL_ENVIRONMENT` also selects the checkpoint bucket |
| `MODAL_SFT_APP_NAME` | The deployed SFT app (default `overmind-sft`) |
| `INFERENCE_API_URL`, `INFERENCE_API_KEY` | The Modal serving endpoint printed by `modal deploy`, and the shared secret it checks |
| `HF_TOKEN` | Gated base models on Hugging Face |
| `AWS_BUCKET_NAME`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION` | The checkpoint archive that backs weights download |

### Billing modes

Leave `STRIPE_SECRET_KEY` empty and the platform runs in **metering mode**: every charge still lands on the credits ledger and shows under Settings, but there is no remaining-credit cap, no `402`, no Free/Pro quota, and no signup grant. Set `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRO_PRICE_ID`, and `STRIPE_CREDIT_PRICE_ID` to turn on the hosted product's plans, top-ups, and the credit gate; point Stripe's `invoice.paid` webhook at `POST /api/billing/webhook/`.

### Optional

`GRAFANA_ADMIN_PASSWORD` and `AWS_PROFILE` for the Grafana service; `SLACK_FEEDBACK_WEBHOOK_URL` to forward Console feedback to a channel; `DJANGO_LOG_LEVEL` and `OVERBAE_LOG_LEVEL` (default `INFO`).
