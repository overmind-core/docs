The platform is one repository, [overmind-core/overmind](https://github.com/overmind-core/overmind): the Django API (`overbae/`), the React Console (`frontend/`), the Python SDK and CLI (`overmind/`), and the Modal workers for training and serving (`overbae/modal/`). The hosted product at [console.overmindlab.ai](https://console.overmindlab.ai) runs this same code.

## Requirements

Docker with Compose, and [uv](https://docs.astral.sh/uv/) for anything Python outside the containers.

The API refuses to start until every required key is set; the error names each missing one.

| Required | Used for |
| --- | --- |
| `OPENROUTER_API_KEY` | Judges, evals, trace scoring, optimiser scoring, frontier inference |
| `MODAL_TOKEN_ID`, `MODAL_TOKEN_SECRET` | Modal training and serving workers |
| `INFERENCE_API_URL`, `INFERENCE_API_KEY` | Serving trained models: the endpoint printed by `modal deploy` and its shared secret |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_BUCKET_NAME` | The fine-tuning checkpoint archive |
| `HF_TOKEN` | Gated Hugging Face base models |
| `SANDBOX_URL`, `SANDBOX_TOKEN` | The [script sandbox](#the-script-sandbox) that runs Data Workshop scripts and extracts documents. Compose sets `SANDBOX_URL`; choose a random token |

| Optional | Effect |
| --- | --- |
| `OPENAI_API_KEY` | The `embedding_cosine` evaluator |
| `STRIPE_SECRET_KEY` | Paid plans and the credit cap — see [Billing modes](#billing-modes) |

Fine-tuning and serving also need the Modal workers deployed — see [Training and serving](#training-and-serving).

## Start the stack

```bash
git clone https://github.com/overmind-core/overmind.git
cd overmind
cp .env.example .env      # set the required keys above
docker compose up -d      # API, Console, Postgres, Redis, five Celery workers, beat, the sandbox, Grafana
```

The Console is at [http://localhost:5173](http://localhost:5173) and the API at `http://localhost:8000`. Sign in with any email and password; self-hosted mode creates the account on first use and needs no email verification. Leave `CLERK_API_SECRET_KEY` blank.

Start by creating a project by following the [Quickstart](/quickstart). The onboarding prompt in your Console already points the coding agent at your API.

To connect a repository by hand instead, run `overmind init --ide <cursor|claude|opencode|codex> --env local`, then `overmind sync` with the temporary account key from the Console. `--env local` points the MCP entry at `http://localhost:8000/api/mcp/`. Sync saves a project-scoped key; reload the coding agent once to connect. For another self-hosted address, set `OVERMIND_API_URL` before both commands.

For a demo workspace with thirty days of traffic, datasets, runs and served models, run the seed with the email you sign in with:

```bash
docker compose exec api python manage.py seed_demo --owner you@example.com
```

## Environment reference

`.env.example` is the operator contract. Every variable is read by `docker-compose.yml` or `overbae/settings.py`; the defaults below are the settings defaults unless Compose overrides them.

### Core

| Variable | Purpose |
| --- | --- |
| `DJANGO_SECRET_KEY` | Django's signing key; the default is an insecure development value |
| `DJANGO_DEBUG` | `True` or `False` (default `False`; Compose sets `True`). Off, Postgres connects with `sslmode=require` |
| `DJANGO_ALLOWED_HOSTS` | Comma-separated hostnames the API answers for |
| `DJANGO_CORS_ALLOWED_ORIGINS` | Comma-separated Console origins; ignored while `DJANGO_DEBUG=True` (all origins allowed) |
| `FIELD_ENCRYPTION_KEY` | Fernet key for stored connector credentials. Unset, one is derived from `DJANGO_SECRET_KEY`; the API prints a warning at startup when `DJANGO_DEBUG=False` |
| `FRONTEND_URL` | Where the Console lives (default `http://localhost:5173`), for links in prompts and emails |
| `TRACE_SETTLE_SECONDS` | How long a trace with no root span stays `live` before it reads `interrupted` (default `600`) |
| `OPENROUTER_API_KEY` | Every routed model call: judges, eval-run generation, the optimiser's scoring and frontier inference. Required at startup. If the key is rejected, the capability's Evaluators tab shows `Judge authoring failed`; fix the key, then run `overmind sync` again |


### The script sandbox

The Data Workshop has no agent. Coding agents add dataset versions with Python scripts over MCP, and the `sandbox` service runs them and extracts uploaded documents (`python -m sandbox`, the same image). Only the landing and interactive workers reach it, over the Compose `sandbox_net` network, which has no route out. The sandbox holds no secrets other than `SANDBOX_TOKEN` and no data volume.

It runs as root so each run gets its own uid, and it needs `CAP_SYS_PTRACE` to count the memory a run holds in files no directory lists. Compose adds it, keeps only the capabilities the server uses (`CHOWN`, `DAC_OVERRIDE`, `FOWNER`, `KILL`, `SETGID`, `SETUID`) and sets `no-new-privileges`. Runs hold no capability. Each run reserves memory before its input is stored; `SANDBOX_MEMORY_BYTES` overrides the budget, which defaults to 60% of the container's memory. `/tmp` is a tmpfs (8 GB in Compose). Document extraction uses Tesseract with English language data, which the image installs.

| Variable | Purpose |
| --- | --- |
| `SANDBOX_URL` | Where the workers reach the sandbox (Compose: `http://sandbox:8080`) |
| `SANDBOX_TOKEN` | Shared bearer token between the workers and the sandbox |
| `SANDBOX_MEMORY_BYTES` | Memory budget for runs (default: 60% of the container's memory) |
| `WORKSHOP_PROJECT_CONCURRENCY` | Script runs at a time per project (default `4`) |

Outside Compose, `make sandbox` runs it on `127.0.0.1:8080` as your own user, without per-run isolation, for local development only.

`OPENAI_API_KEY` serves embeddings (`text-embedding-3-small`) for the `embedding_cosine` statistical evaluator.

### Decision engine

For [Jev decisions](/agent-testing/decision-engine), the existing OpenRouter key
and shared Redis cache also provide decision routing and account-wide pacing.
`JEV_REQUESTS_PER_MINUTE` (default `1200`) and `JEV_TOKENS_PER_SECOND` (default
`250000`) should match the account allowance. Missing configuration or unavailable
capacity falls back to generative judging; Jev is not a chat or inference model.

### Training and serving

| Variable | Purpose |
| --- | --- |
| `FINETUNING_BACKEND` | `modal`, the only accepted value |
| `MODAL_TOKEN_ID`, `MODAL_TOKEN_SECRET`, `MODAL_ENVIRONMENT` | Required (tokens). Modal training and serving workers, deployed with `modal deploy overbae/modal/modal_vllm_worker.py`, `register_model.py` and `modal_sft_worker.py` (`--env $MODAL_ENVIRONMENT`). `MODAL_ENVIRONMENT` (default `overmind-dev`) also selects the checkpoint bucket |
| `MODAL_SFT_APP_NAME` | The deployed SFT app (default `overmind-sft`) |
| `INFERENCE_API_URL`, `INFERENCE_API_KEY` | Required. The Modal serving endpoint printed by `modal deploy`, and the shared secret it checks |
| `HF_TOKEN` | Required. Gated base models on Hugging Face |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_BUCKET_NAME`, `AWS_REGION` | Required (all but the region). The checkpoint archive that backs weights download |

The Modal workers read their credentials from a Modal secret named `overmind-inference`: the AWS keys, `INFERENCE_API_KEY` and `HF_TOKEN`.

### Billing modes

Leave `STRIPE_SECRET_KEY` empty and the platform runs in **metering mode**: every charge still lands on the credits ledger and shows under Settings, but there is no remaining-credit cap, no `402`, no Free/Pro quota, and no signup grant. Set `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRO_PRICE_ID`, and `STRIPE_CREDIT_PRICE_ID` to turn on the hosted product's plans, top-ups, and the credit gate; point Stripe's `invoice.paid` webhook at `POST /api/billing/webhook/`.

### Optional

`GRAFANA_ADMIN_PASSWORD` (default `admin`) and `AWS_PROFILE` for the Grafana service; `SLACK_FEEDBACK_WEBHOOK_URL` to forward Console feedback to a channel; `DJANGO_LOG_LEVEL` and `OVERBAE_LOG_LEVEL` (default `INFO`).


## Background capacity

Keep the `celery-landing-worker` service running. It consumes only `landing`, with one prefork process, so evaluation generation cannot occupy import capacity. The other worker queues remain `control`, `io`, `io_traces`, `batch` and `interactive`; `interactive` runs Data Workshop scripts through the sandbox, and each run waits for a per-project slot in Redis and for the sandbox's memory.

Evaluation samples wait in Postgres until the dispatcher admits them. `EVAL_MAX_IN_FLIGHT` limits admitted work across the deployment (default `12`); `EVAL_MAX_IN_FLIGHT_PER_RUN` limits each run (default `2`). Admission rotates across projects and runs. Coordinate these limits with worker capacity and provider limits. Increasing the worker count alone does not raise the admission budget.

`DATASET_IMPORT_MAX_QUEUE_SECONDS` sets the maximum import wait (default `900`). An expired wait retains the source and exposes **Retry import**. Execution starts its own deadline when a worker claims the import. Keep beat and the control worker running so publication retries and interrupted imports are reconciled.

For ECS deployments, `docker/worker-topology.json` defines worker commands, including `sandbox`, and `scripts/plan_landing_capacity.py` generates the infrastructure plan. Deploy the sandbox, then a healthy landing consumer, before producers. Configure queue-age, blocked-import and missing-monitor alarms. The generated scaling plan has explicit capacity bounds and disables automatic scale-in; drain work before reducing capacity.

## Developing on it

```bash
make worker                # one local Celery worker over every queue, solo pool
make test                  # backend tests, parallel (make test-serial to debug)
make lint-format           # ruff + biome + tsc
make check-migrations      # after a model change
make generate_api_client   # after any backend API change: regenerates frontend/src/openapi/
cd frontend && bun run typecheck && bun run lint && bun run test
```

`AGENTS.md` at the repo root is the playbook a coding agent reads before touching a subsystem; `.claude/skills/` holds the subsystem maps. Pull requests go against `main`; `oss` is based on `main` and carries the same code with the in-repo SDK. `sdk-publish.yml` builds and publishes the SDK to PyPI on pushes to `main` that touch `overmind/` and on published GitHub releases.
