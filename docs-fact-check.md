# Documentation fact check — 22 October 2026

Reviewed all 40 public MDX pages and the linked `frontend/public/setup.md` against platform commit `809e22a9d50f48929b201e12fb35035ed82d7bde`. The platform working tree contained unrelated untracked benchmark files; they were not part of the implementation reviewed and were left untouched. The only platform file edited in this review is the public setup document.

## Conclusion

The central workflow is supported by the code: a native coding agent can prepare the fraud data, train a qualified decision model and launch a held-out benchmark through MCP and CLI operations. This is an agent-coordinated workflow, not an upload-triggered autonomous platform agent. Data checks, explicit preparation and launch, consumer pinning and result inspection remain separate operations that the coding agent performs from the user's request.

This is a source-and-contract verification. It does not certify the currently hosted release, a particular GPU image, provider availability, training quality, cost or successful completion of the example prompt. No live platform requests, training, evaluation, inference or credential changes were performed.

## Code inconsistency found outside the docs

`CreateEvalMatrixRowInput.source` in `overbae/services/mcp/contracts/evaluations.py:84` advertises returning `{score, reason}`. The actual deterministic executor in `overbae/innermind/deterministic.py:275` accepts a boolean, numeric score, a two-item tuple/list, or `None`; dictionaries become an error.

The docs correctly document the executor's supported return forms. This review leaves executable code and MCP schema metadata unchanged and records the mismatch for a separate implementation correction. An agent relying only on that schema description could still author an invalid evaluator.
