A dataset is the data your eval runs, optimiser runs, and training runs read. You bring the rows. The dataset's agent shapes them until they fit, and tells you plainly when they cannot.

<Steps>
  <Step title="Create">
    Upload a file, paste rows, or select traces.
  </Step>
  <Step title="First scan">
    The agent makes the rows valid and runs quality checks, on its own.
  </Step>
  <Step title="Review">
    Read what it did. Ask for changes in the chat.
  </Step>
  <Step title="Use">
    Hand the version to **Train a model** or **Run the optimiser**.
  </Step>
</Steps>

## Create

Open **New dataset** on the Datasets page, choose a source, and pick what the data is for.

<Frame caption="The New dataset dialog with Train + eval selected.">
  <img src="/images/platform/new-dataset-dialog.jpg" alt="New dataset dialog with the Train + eval purpose selected" />
</Frame>

<Tabs>
  <Tab title="Upload or paste">
    Drop a **CSV, TSV, JSON, JSONL, or Parquet** file on the Datasets page, or paste rows into the dialog. Text files may be gzipped.

    Your values land as they are. A file that cannot be read faithfully is refused with the reason, never silently changed.
  </Tab>
  <Tab title="From traces">
    Select traces in [Observability](/core/observability#from-traces-to-datasets) and **Add to dataset**, or choose **From traces** in the dialog to land every trace that matches the current filters. Each trace becomes one row with its input, output, full conversation, and score.
  </Tab>
</Tabs>

| Purpose | What you get |
| --- | --- |
| **Decide from the rows** | The agent works out whether the rows are training or evaluation data |
| **Training** | A dataset for [Training](/models/training) |
| **Evaluation** | A dataset for [Eval runs](/agent-testing/eval) and the [Optimiser](/agent-testing/optimisers) |
| **Train + eval** | Two datasets from one source, `<name> train` and `<name> eval`, with no rows in common. You choose the eval share and whether it comes from the first rows, the last rows, or a random draw |

## First scan

When the source has landed, the agent takes one turn by itself:

1. It decides what the data is for, if you left that open.
2. It makes the rows valid — for example by building conversations from `prompt` and `completion` columns, or renaming `question` and `answer`, and dropping rows that cannot be used.
3. It runs quality checks — duplicates, empty answers, outliers, broken tool calls — and fixes what it finds.

Each change is one **cell**, and you can read every one. A fix that would remove half your rows or more is never applied for you: it waits in the chat as a proposal with **Run** and **Discard**.

If the rows cannot be used at all — a table of numbers and ids with no text — the agent says so and changes nothing.

## Review and change

<Frame caption="The Data Workshop: versions on the left, cells in the middle, the agent on the right.">
  <img src="/images/platform/workshop.jpg" alt="Data Workshop with cells and the dataset agent" />
</Frame>

- Every cell that ran is a **version**: the source is 1.0, then 1.1, 1.2, and so on. Nothing is edited in place, so you can always compare a version with the one before it.
- To change the data, ask in the chat: "drop answers under ten words", "keep only billing tickets". The agent adds a cell and runs it. You can also rename the dataset or change what it is for from the chat.
- You can write and edit cells yourself. A cell is a short Python script over a pandas frame named `df`.
- The chip under the active version reads **Fits** when it is ready to use. When it does not, the chip says why and offers **Ask Overmind to fix it**.

## What valid rows look like

<Tabs>
  <Tab title="Training">
    A `messages` column holding a conversation that ends with the assistant:

    ```json
    {"messages": [
      {"role": "system", "content": "You triage support tickets."},
      {"role": "user", "content": "My card was declined twice."},
      {"role": "assistant", "content": "Route to billing. Priority: high."}
    ]}
    ```

    This is the OpenAI chat format. Rows that call tools also carry a `tools` column with the tool definitions.
  </Tab>
  <Tab title="Evaluation">
    An `input` on every row, and an `expected_output` to score against:

    ```json
    {"input": "My card was declined twice.", "expected_output": "billing"}
    ```

    `input` can be text, an object, or a conversation. Other columns are kept as they are.
  </Tab>
</Tabs>

Your file does not need to arrive in this shape. Getting it there is the first scan's job.

## Use a version

The active version offers **Train a model** for training data, and **Run the optimiser** or **Use in a training job** for evaluation data. You can also export any version as JSONL or CSV.

A run locks the version it read, so its results always point at the exact data behind them. Later changes become new versions. Checking readiness or a launch that is refused locks nothing.

## When something is refused

| Message | Fix |
| --- | --- |
| `Row 12 has 3 cells; the header has 2.` | A CSV cell contains a comma. Quote it, or use JSONL |
| `Column 'notes' appears twice.` | Rename one of the columns |
| `The file is not UTF-8.` | Save the file as UTF-8 and upload again |
| `Line 40 is not valid JSON` | Fix that line. Nothing is skipped silently |
| `Two rows are needed to split.` | Add rows, or create a single dataset |
| `no messages column` / `no input column` | Click **Ask Overmind to fix it** |
| `no text in any column` | The rows hold only numbers and ids. Use a different source |
| `X is a train dataset; this needs eval.` | Pick an evaluation dataset |
| `N rows … also appear in … (same trace_id)` | Training and evaluation data overlap. Create them with **Train + eval** |
| `Longest dataset row is ≈N tokens but this model's … context is M` | Drop or shorten the long rows, or pick a model with a longer context |
| `The dataset is busy.` | The agent or a run is working. Wait for it to finish |

## Limits

| Limit | Value |
| --- | --- |
| Upload size | 2 GB |
| A single `.json` document | 256 MB — use JSONL above that |
| Text encoding | UTF-8 |
| One cell's run time | 300 seconds |

## From the CLI and coding agents

```bash
# Upload a file and wait until it is ready
overmind dataset upload transcripts.jsonl --intent train --wait

# One file as a train dataset and an eval dataset
overmind dataset upload tickets.jsonl --split 20 --wait

# Download a version
overmind dataset export <dataset-id> --cell 1.2 --output rows.jsonl
```

See the [CLI](/platform/cli#overmind-dataset). Coding agents get the same workflow through [MCP](/platform/mcp), and every endpoint is in the [API reference](/platform/api#building-a-dataset).

<Tip>
Start small and real: 10–50 representative rows from your traces beat a thousand synthetic ones.
</Tip>
